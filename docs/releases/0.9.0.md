# 0.9.0 — Glamsterdam: Sepolia Amsterdam activation on 2026-10-06

Promotion of `staging` (0.8.x series, through 0.8.41) to `main`. 0.9.0 is the release that follows Ethereum's
**Amsterdam** (Glamsterdam, execution layer) hard fork. **Sepolia activates Amsterdam at timestamp `1791294816`,
2026-10-06 13:53:36 UTC.**

## Who must upgrade, and by when

- **Every Sepolia operator: upgrade to 0.9.0 before 2026-10-06 13:53 UTC.** A node on an older build cannot
  validate the first Amsterdam block, stops following the chain there, and its fork id (`0x268956b6`, next
  `1791294816`) no longer matches its peers' (`0x6c1d9423`). It is refused at the `Status` handshake.
- **Platåberget** (the public Glamsterdam testnet, chain id 7091047534) has been in Amsterdam since 2026-08-20;
  following its head needs 0.9.0.
- **Ethereum mainnet** has no Amsterdam date yet; none is scheduled in fukuii's config.
- Run the CL client your network's release names for Gloas (Sepolia: epoch 353024). The EL and CL fork at the same
  time.

## Ethereum Classic and Mordor: unaffected

Every Amsterdam rule is gated on `amsterdam-timestamp`, which no ETC-family chain declares (a test fails the build
if one ever does). ETC mainnet, Mordor and Gorgoroth need no action for Glamsterdam, and **Olympia stays deferred
on every chain** until a confirmed test block exists (shipped in 0.8.9). Shared VM and ledger changes in this
release were reviewed against ETC's rules, and the ETC suites pass.

One fix reaches every chain, ETC included: fork recovery no longer swallows the import's `ImportDone` and wedges
regular sync (#1432).

Platåberget soak fixes (#1460-#1481, details in the [changelog](https://github.com/chippr-robotics/fukuii/blob/main/CHANGELOG.md)):

- **Import performance:** JUMPDEST analysis once per contract per block (#1460, #1463, #1477), read-through caches
  for contract code and decoded trie nodes, a parallel prefetch of an Amsterdam block's accounts, slots and code
  from its block access list (#1467), and block access lists fetched from eth/71 peers during catch-up (#1468).
  On the soak, heavy 190M-gas blocks went from 64-86 s to 10-12 s once the caches held the working set (#1477).
- **Import atomicity and reference counts (every chain, basic pruning):** per-block atomic state commits and
  adoption of a failed batch's validated prefix (#1465), per-hash serialisation of execution and commit (#1481),
  and undo of non-canonical blocks' reference-count changes on reorg, forkchoice moves and SYNC-FORK rewinds
  (#1471, #1473, #1474). These addressed "Missing account trie node" errors caused by blocks applied twice or
  abandoned without undo.
- **SNAP sync:** the storage-ordering, heal re-peg and Path-scheme fixes (#1449, #1450, #1453-#1455, #1480), healing
  that is never declared clean on a dirty or superseded pass (#1472), deferred body and receipt backfill on
  ETH-family networks (#1466), missing-code recovery (#1456, #1459), snap-peer rotation and retention (#1470,
  #1479), and replacement of an unservable pivot (#1478).
- **Engine API:** an already-executed side payload answers VALID without re-execution (#1478).
- **VM:** a failed CREATE / CREATE2 keeps its memory expansion (#1461).

Evidence: the execution-specs `tests@v21.0.0` Amsterdam corpus passes 26,503 / 26,503 through block import in CI, the
payload builder rebuilds its 27,352 blocks with identical hashes, and hive `rpc-compat` and `graphql` are unchanged.

## Upgrade steps

1. Download the 0.9.0 release assets (or pull the image) and verify them as for previous releases.
2. Stop the node and replace the binary. A datadir from 0.8.x needs no migration step. Amsterdam block access lists are stored in a
   new namespace.
3. Start it with the same configuration and the same JWT secret. The Engine API must stay enabled for post-merge
   networks (`fukuii.network.engine-api.enabled = true`).
4. Confirm the version, that the CL is connected, and that the node is at the head. Peers should accept the fork
   id `0x268956b6`, next `1791294816`.
5. After 13:53:36 UTC on 2026-10-06, the head should pass the first Amsterdam block and the fork id become
   `0x6c1d9423`.

Do this before the fork, not at it.

## Operator notes

- **eth/70 and eth/71 are now advertised** on Ethereum, Sepolia and Platåberget (#1475). Peers that offer only
  eth/68-69 negotiate down. ETC, Mordor and Gorgoroth are unchanged; eth/72 and snap/2 stay off.
- **`state-read-caches` sizes (#1476).** A byte-size key that is set explicitly (for example `code-cache-bytes`,
  `jumpdest-cache-bytes`, `decoded-node-cache-bytes`) is used as given and held with strong references. Each
  explicit cache is clamped to 50% of the max heap, and explicit caches totalling more than 60% are scaled down
  with a WARN. Keep the total at 35% of the heap or less; the rest is working heap and the page cache RocksDB
  needs. Keys left unset keep the conservative defaults, capped at a fraction of the heap. Each cache's effective
  size is logged at INFO at startup.
- **Sizing on a modest host.** An 8 GB heap with large explicit caches reached 11.5 GB resident on the 16 GB soak
  host. The soak runs at `-Xmx6g` with a 1.5 GiB code cache. Pruning stays at the default (`pruning.mode =
  "basic"`, `history = 64`); the atomicity and reference-count fixes above apply to it.
- **SNAP on ETH-family networks** defers body and receipt backfill until state is finalised
  (`fukuii.sync.snap-sync.defer-chain-backfill-until-state-complete`, #1466).

If a CL proposes through fukuii: since 0.8.13, every engine payload moves the gas limit toward
`mining.gas-limit-target` (default 60,000,000), before Amsterdam too, as go-ethereum's builder does. It used to keep
the parent's limit. Set `mining.gas-limit-target` to vote for a different limit.

## Known issues

- **Import speed on modest hardware.** On the soak host (4 cores, 16 GB, DRAM-less SATA SSD with dm-crypt), 190M-gas
  devnet blocks import in about 8-10 s warm, longer than the roughly 6.5 s slot, so Lighthouse can briefly mark the
  execution client offline. Import time has not been measured on Sepolia or Ethereum mainnet.
- **SNAP healing convergence.** On a large or high-churn state, healing can fall back to the lazy state-fetch
  handoff instead of converging. Follow-up work is tracked. Platåberget has only two snap/1-serving peers, which
  limits SNAP there. Sync before the fork, or keep an already-synced datadir. Regular sync
  (`fukuii.sync.do-snap-sync = false`) imports from genesis.
- Not implemented, and not needed to follow the chain: the sparse blobpool (eth/72) and `engine_getBlobsV3` / `V4`
  ([#1431](https://github.com/chippr-robotics/fukuii/issues/1431)). fukuii fetches access lists from eth/71 peers
  only to prefetch state (#1468).
- `eth_getBlockByNumber` and `eth_getBlockByHash` do not yet report an Amsterdam header's `blockAccessListHash` and
  `slotNumber`.
- hive `consume-*` suites against Amsterdam have not been run yet, and the Sepolia fork boundary itself is validated live on 2026-10-06.
