# 0.9.0 — Glamsterdam (Amsterdam) for Ethereum networks

Promotion of `staging` (the 0.8.x series) to `main`. 0.9.0 is fukuii's Glamsterdam release: it carries
the Amsterdam execution-layer rule set ([EIP-7773](https://eips.ethereum.org/EIPS/eip-7773)) that
Sepolia activates on **2026-10-06 13:53:36 UTC**. Per-EIP detail is in
[Glamsterdam](../specifications/GLAMSTERDAM.md); the full change list is in the
[CHANGELOG](https://github.com/chippr-robotics/fukuii/blob/main/CHANGELOG.md).

## Sepolia operators: upgrade before 2026-10-06 13:53:36 UTC

- Sepolia activates Amsterdam at timestamp `1791294816`. A fukuii node on a build without Amsterdam
  support stops following Sepolia at the first Amsterdam block: it cannot validate that block, and its
  fork id no longer matches its peers'. The first build that carries the whole rule set is 0.8.13;
  0.9.0 is the release to run.
- Upgrade from any earlier build regardless: before 0.8.13, a Sepolia block carrying an EIP-6110 deposit
  was rejected as `INVALID_REQUESTS` (#1416, below).
- Pair fukuii with a Gloas-ready consensus client over the authenticated Engine API
  (`fukuii.network.engine-api`, with a JWT secret). From Amsterdam the CL calls `engine_newPayloadV5`,
  `engine_forkchoiceUpdatedV4` and `engine_getPayloadV6`.
- Until the fork, fukuii announces Sepolia's fork id as `0x268956b6` with next `1791294816`; from the
  fork, `0x6c1d9423`. A peer that disagrees is refused at the `Status` handshake.
- Validators proposing through fukuii: see the gas-limit change under [Upgrade notes](#upgrade-notes).

Glamsterdam does not apply to Ethereum Classic, Mordor or Gorgoroth. Their operators should still read
the Olympia and fast-sync notes under [Upgrade notes](#upgrade-notes).

## Glamsterdam execution layer

- **EIPs:** 2780, 7708, 7778, 7843 (`SLOTNUM`), 7928 (block-level access lists), 7954, 7976, 7981, 8024
  (`DUPN`, `SWAPN`, `EXCHANGE`), 8037, 8038, 8246 and 8282 (builder execution requests). EIP-7997 needs no
  client code. Each rule is keyed on the chain's `amsterdam-timestamp`, which no ETC-family chain config
  declares.
- **Block-level access lists (EIP-7928):** built while a block executes, checked against the header's
  `blockAccessListHash`, stored, and served by `engine_getPayloadBodiesBy*V2` and eth/71.
- **Engine API:** `engine_newPayloadV5`, `engine_forkchoiceUpdatedV4`, `engine_getPayloadV6`,
  `engine_getPayloadBodiesByHashV2` and `engine_getPayloadBodiesByRangeV2`.
- **Block building:** fukuii proposes Amsterdam blocks, with the 23-field header, the payload attributes'
  slot number, the block's own access list, EIP-8282 builder requests and EIP-8037's per-dimension
  transaction packing.
- **Networking:** the fork id follows the chain head's timestamp in the `Status` handshake, the ENR and
  DNS discovery. eth/71 serves stored access lists within go-ethereum's 2 MiB / 1,024-entry limits
  (opt-in, below).
- **JSON-RPC:** `eth_config` reports the EIP-8282 builder contracts; the txpool's pre-filter follows the
  fork active at the chain head; `eth_estimateGas` starts at `max(intrinsic gas, calldata floor)`;
  `eth_simulateV1` builds the 23-field header; trace and debug replays of an Amsterdam block re-execute it
  as block import did.

## Fixes on live networks

Found while bringing up the Amsterdam corpus; each applies before Amsterdam too.

- **Sepolia deposits (#1416):** execution read EIP-6110 deposits only from the mainnet deposit contract,
  so since Prague a Sepolia block carrying a deposit computed the wrong `requestsHash` and was rejected.
- **EIP-7623 (#1438):** from Prague, a transaction whose gas is below its calldata floor is invalid; it
  was executed.
- **Transient storage (#1439):** from Cancun, a successful precompile CALL keeps the caller's transient
  storage; it was wiped.
- **P256VERIFY (#1439):** from Osaka, a failed verification returns empty output.
- **EIP-7934 (#1439):** from Osaka, the Engine API path enforces the block size limit.
- **MODEXP (#1441, 0.8.6):** a length word cut short by the end of the input is read right-padded with
  zeros, on every network that has the precompile, ETC included.
- **RLP (#1442, 0.8.7):** decoding caps list nesting depth at 64, so a deeply nested message is refused
  instead of crashing the node.

## Also in the 0.8.x series

- **Fast sync removed (#1436):** SNAP or regular sync only. See [Upgrade notes](#upgrade-notes).
- **Olympia deferred on every chain (#1445)** until a confirmed test block exists. Gorgoroth and the
  private-network template now leave it unscheduled, as ETC mainnet and Mordor already did.
- **Sync:** post-merge regular sync recovers from a rewind, and fork recovery no longer wedges regular
  sync on any chain (#1432); SNAP sync finishes after state healing re-pegs its pivot (#1448).
- **`eth_simulateV1` (#1446):** per-call overrides no longer reach block import or other RPC calls.
- **Peers (#1447):** a handshaked peer no longer reconnects itself when its connection drops.
- **External IP (#1410, #1411):** detection is configurable, and every candidate is validated as a public
  IPv4 address before it is advertised.
- **EVM (#1408):** about 5x interpreter throughput on arithmetic-heavy code.
- **Engine API and P2P interop from hive (#1408):** go-ethereum-compatible payload building, forkchoice
  and receipt encoding; go-ethereum now dials fukuii.
- **CI (#1406):** every gate's tier is declared in `.github/gates.yml` and published in
  [Verification Status](../STATUS.md).

## Known limitations

- **Sparse blobpool (EIP-8070, #1431):** not implemented. The eth/72 capability is opt-in and off by
  default; hive's `GetCells` and `BlobTxWithInvalidCells` are declared waivers.
- **`engine_getBlobsV3` / `engine_getBlobsV4` (#1431):** not implemented.
- **snap/2 (EIP-8189):** opt-in and off by default. snap/2 drops `GetTrieNodes`, which trie healing needs
  on a chain without block access lists; negotiating the snap version per peer is #1431.
- **eth/70, eth/71, eth/72 and snap/2** are off by default (`network.protocols`); a network config has to
  opt in (the hive config does).
- **`eth_getBlockByNumber` / `eth_getBlockByHash`** do not report an Amsterdam header's
  `blockAccessListHash` and `slotNumber`.
- **`eth_simulateV1`** records no access list: a simulated Amsterdam block reports the empty list's hash
  and slot number 0.
- **Calls built from RPC arguments** (`eth_call`, `eth_createAccessList`, `debug_traceCall`, `trace_call`
  and similar) run on the bare VM, without an EIP-7702 authorization list or the calldata floor; see
  [What the bare VM leaves out](../specifications/GLAMSTERDAM.md#what-the-bare-vm-leaves-out).

## Upgrade notes

- **Proposers, every fork:** Engine API payloads now move the gas limit toward the node's gas ceiling,
  as go-ethereum's builder does: an Amsterdam payload's `targetGasLimit` when the attributes carry one,
  and otherwise `mining.gas-limit-target` (default 60,000,000). A payload used to keep its parent's
  limit. Set `mining.gas-limit-target` to vote for a different limit.
- **Fast sync is gone.** Its configuration keys under `fukuii.sync` are ignored with a startup warning;
  `fukuii_resetFastSync`, `fukuii_restartFastSync` and the `app_fastsync_*` metrics are removed. A node
  that set `do-fast-sync = false` to sync from genesis should set `do-snap-sync = false`. A node stopped
  part-way through fast sync resumes with SNAP sync. Details are in the CHANGELOG.
- **Gorgoroth:** Olympia is no longer scheduled at 15,800,850. Move every node to this release together,
  and reset any datadir that ran past 15,800,850 on an Olympia-active build.
- **Ethereum mainnet:** nothing is scheduled; the live-network fixes above apply from their own forks.
