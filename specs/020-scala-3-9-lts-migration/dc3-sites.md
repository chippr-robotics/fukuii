- **374 are RLP codecs.** `RLPImplicits` defined each base codec three times: a named intersection given
  `xEncDec: RLPEncoder[X] & RLPDecoder[X]` and two anonymous givens, `RLPEncoder[X]` and `RLPDecoder[X]`. All three
  are the same `private val xCodec`. The old rule picks the named intersection because it is more specific; 3.7 picks
  the anonymous one because it is more general. At runtime both choices are the **same object**. For `Seq[T]`, both
  givens call `seqCodec[T]`, so the codec class and the encoding are the same.
  - **Fix**: remove the anonymous duplicates at the definition site (step c). The named given becomes the only
    candidate, which is the old rule's choice, so every one of the 374 sites keeps its instance.
- **7 are MCP `JsonMethodDecoder` choices** in `JsonRpcController.handleMcpRequest`. The old rule picks `mcpXCodec`;
  3.7 picks `mcpXRequestDecoder`. These are different instances: the codec's `decodeJson` delegates to the decoder.
  - The same `handle(...)` clause also takes a `JsonEncoder[Res]`. It raises no E205, but `javap` on the 3.6 classes
    shows that **both** arguments are `mcpXCodec` today: `McpJsonMethodsImplicits$.mcpXCodec()` is invoked twice at
    each of the seven sites.
  - **Fix**: pass both explicitly as `(using mcpXCodec, mcpXCodec)` (step d), which pins today's selection. The
    same file already does this for `personal_signTransaction` and `personal_sign`.
